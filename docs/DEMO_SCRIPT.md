# 뷰티링크 데모 시나리오

> 미용실 원장님·네이버예약 제휴 검토자에게 시연할 때 사용하는 실전 가이드

---

## 사전 준비

- URL: Vercel 배포 주소 또는 `http://localhost:3000`
- 데모 계정: 원장(owner) 계정으로 로그인 → 모든 기능 시연 가능
- 모바일 시연 시: 크롬 DevTools > iPhone 15 Pro (390px) 에뮬레이션 또는 실기기

---

## ⚡ 3분 데모 시나리오

> 타깃: 빠른 의사결정자, 개요만 보고 싶은 원장님

| 순서 | 화면 | 포인트 |
|------|------|--------|
| 1 | `/dashboard` | 오늘 예약 건수·매출·노쇼를 한눈에 확인 |
| 2 | `/calendar` (월간 뷰) | 이번 달 전체 예약 현황 + 날짜 클릭 → 당일 목록 |
| 3 | `/reservations/new` | 고객·디자이너·시술 선택 → 예약 등록 (30초) |
| 4 | `/customers` | 고객 검색 → 방문 이력·노쇼 횟수 확인 |
| 5 | `/integrations/naver` | 네이버예약 매핑 준비 화면 (연동 준비율 확인) |

**클로징 멘트**: "지금 보신 화면이 실제 서비스와 동일합니다. 네이버예약 API 승인 후 바로 연동 가능합니다."

## 🕐 10분 데모 시나리오

> 타깃: 도입 검토 중인 원장님, 기능 상세 확인 원하는 분

### 1단계 — 대시보드 (1분)

- `/dashboard` 접속
- **포인트**: 오늘 예약 건수 / 신규 고객 / 매출 / 노쇼 건수 카드 확인
- **멘트**: "매일 아침 이 화면 하나로 오늘 운영 상황을 파악할 수 있습니다"

### 2단계 — 예약 등록 (2분)

- `/reservations/new` 접속
- 고객 선택 (드롭다운 + 이름 검색)
- 디자이너 선택 → 해당 디자이너 근무 시간 기반으로 타임슬롯 표시
- 시술 선택 → 소요시간 자동 계산
- 예약 경로: 네이버 / 전화 / 방문 중 선택
- **포인트**: 같은 시간 다른 예약과 겹치면 "중복 예약 경고" 표시
- **멘트**: "전화 예약이 들어와도 30초 안에 등록할 수 있습니다"

### 3단계 — 캘린더 (2분)

- `/calendar` 접속 → 월간 뷰 클릭
- 이번 달 전체 예약 현황 그리드 확인
- 날짜 클릭 → 우측 사이드바에 당일 예약 목록
- 주간 뷰 전환 → 디자이너별 시간대 확인
- 일간 뷰 전환 → 시간대별 상세 예약
- **멘트**: "일·주·월 3가지 뷰로 언제든 스케줄을 확인할 수 있습니다"

### 4단계 — 고객 관리 (2분)

- `/customers` 접속
- 고객 검색 → 상세 페이지 진입
- **포인트**: 방문 이력 타임라인, 시술 메모, 노쇼 횟수
- 연락처는 010-****-5678 형태로 마스킹 → 원장 계정에서는 전체 번호 확인 가능
- **멘트**: "고객 방문 이력이 쌓일수록 재방문 유도와 맞춤 서비스가 가능해집니다"

### 5단계 — 디자이너 & 시술 관리 (1분)

- `/designers` → 근무시간·휴무일 설정 확인
- `/services` → 시술 메뉴 가격·소요시간 확인
- **멘트**: "디자이너별 가능한 시술과 스케줄이 예약 등록에 바로 반영됩니다"

### 6단계 — 문자·알림톡 관리 (1분)

- `/messages` 접속
- 메시지 템플릿 5종 확인 (예약확정, 리마인드, 취소, 노쇼, 재방문)
- 발송 이력 확인
- **포인트**: 실 발송은 SMS/알림톡 API 계약 후 활성화. 현재는 Mock 상태
- **멘트**: "템플릿 준비는 완료되어 있습니다. API 계약 후 바로 활성화됩니다"

### 7단계 — 네이버예약 연동 준비 (1분)

- `/integrations/naver` 접속
- 상점 ID / 매장명 / 네이버플레이스 URL 입력 화면
- 디자이너 매핑 (내부 디자이너 ↔ 네이버 예약 이름)
- 시술 메뉴 매핑 (내부 메뉴 ↔ 네이버 메뉴)
- 연동 준비율 퍼센트 확인
- **멘트**: "API 승인 전에 미리 매핑을 완료해두면 승인 즉시 자동 연동됩니다"

## 🏪 원장님 전용 시연 순서

> 실제 도입 여부를 고민하는 미용실 원장님

1. **대시보드** — "오늘 매출·예약 한눈에"
2. **예약 등록** — "전화 오면 30초 등록"
3. **캘린더 (월간)** — "이번 달 전체 현황"
4. **고객 관리** — "방문 이력·노쇼 고객 파악"
5. **디자이너 스케줄** — "누가 언제 쉬는지 바로 확인"
6. **문자 템플릿** — "노쇼 줄이는 리마인드 준비"
7. **설정** — "매장 이름, 직원 권한 관리"

**강조 포인트**:
- 복잡한 엑셀 없이 → 예약·고객·매출을 한 화면에서
- 디자이너가 직접 본인 예약 확인 가능 → 원장 부담 감소
- 네이버예약도 같은 화면에서 통합 관리 (API 승인 후)

## 🔗 네이버예약 제휴 검토자 전용 시연 순서

> 네이버 측 제휴 담당자 또는 파트너에게 시연할 때

1. **대시보드** — 시스템 전체 구조 파악
2. **네이버예약 연동 준비** (`/integrations/naver`) — **핵심 화면**
   - 상점 ID / 매장명 / 네이버플레이스 URL 입력 필드
   - 디자이너 1:1 매핑 테이블
   - 시술 메뉴 1:1 매핑 테이블
   - 연동 준비율 progress bar (5항목 기준: 상점ID 20 + 매장명 10 + URL 10 + 디자이너 30 + 시술 30)
3. **캘린더** — 예약이 연동될 화면 미리 보기
4. **예약 등록** — 네이버 경로 선택 가능 (네이버/전화/방문)
5. **보안 설정** (`/security`) — 접근 로그, 권한 관리 체계

**강조 포인트**:
- API 승인 없이도 내부 매핑 설정 가능 → 도입 장벽 최소화
- 기존 예약(전화/방문)과 네이버예약을 동일 캘린더에 통합
- Firestore 기반 실시간 데이터 → 확장성 보장

## 자주 받는 질문 (Q&A)

**Q. 네이버예약과 실제로 연동이 되나요?**
A. 현재는 연동 준비 단계입니다. 네이버 공식 API 제휴 승인 후 바로 활성화 가능한 구조로 설계되어 있습니다.

**Q. 문자 발송이 실제로 되나요?**
A. 현재는 Mock 상태입니다. SENS API 또는 카카오 알림톡 API 계약 후 바로 연동 가능합니다.

**Q. 데이터는 어디에 저장되나요?**
A. Firebase Firestore (Google Cloud 기반)에 저장됩니다. 매장별로 데이터가 완전히 분리되어 있습니다.

**Q. 여러 매장 관리가 가능한가요?**
A. 현재는 단일 매장 기준으로 구현되어 있으며, 멀티 매장 지원은 로드맵에 포함되어 있습니다.

**Q. 모바일에서도 사용 가능한가요?**
A. 네, 완전 반응형으로 설계되어 있습니다. iOS Safari, Android Chrome 모두 지원합니다.
